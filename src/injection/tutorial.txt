================================================================================
ASPIS FAULT INJECTION FRAMEWORK - QUICK START GUIDE
================================================================================

This framework allows you to evaluate C programs against automated Register 
and Memory fault injection campaigns, proving the efficacy of ASPIS mitigations.

--------------------------------------------------------------------------------
STEP 1: WORKSPACE SETUP
--------------------------------------------------------------------------------
Create a dedicated folder for your new benchmark inside the main fault_injection
directory. Place your C source code here and create a compiled/ subfolder.

testing/tests/c/test_benchmarks/your_program.c      <-- Your C source code
should also update a file with expected output (TODO)

fault_injection/
├── run_all.sh
├── run_campaign.sh
├── profile_target.py
├── inject_registers.py
├── inject_memory.py
└── your_program/                <-- Create this folder
    ├── targets.cfg              <-- Your configuration file
    └── compiled/                <-- Created automatically for binaries

--------------------------------------------------------------------------------
STEP 2: COMPILATION
--------------------------------------------------------------------------------
./compile_all.sh your_program

--------------------------------------------------------------------------------
STEP 3: CONFIGURATION (targets.cfg)
--------------------------------------------------------------------------------
Create a targets.cfg text file inside your_program/. Add one line per target 
function using this exact space-separated format:

TARGET_FUNC PAYLOAD_PTR LENGTH_VAR DATA_TYPE_SIZE

* TARGET_FUNC:    The name of the C function to attack (e.g., sort)
* PAYLOAD_PTR:    The pointer/array variable name (e.g., v)
* LENGTH_VAR:     The variable defining the element count (e.g., l)     //lo fai fare a gdb
* DATA_TYPE_SIZE: The byte size of a single element (e.g., 4 for int)

Example targets.cfg:
sort v l 4
process_matrix matrix size 8

(Note: If a function does not use a dynamic array, leave the last three columns 
blank).

--------------------------------------------------------------------------------
STEP 4: EXECUTION
--------------------------------------------------------------------------------
Option A: Standard Mode (Chaotic Noise)
Attacks the full active register set and safe stack frame. (less precise)
$ ./fault_injection/run_all.sh your_program

Option B: Data-Only Mode (Surgical Adversarial)
Filters registers to exclude pointers and uses targets.cfg to strike exactly 
inside the mathematical boundaries of your data payload.
$ ./fault_injection/run_all.sh your_program --data-only

--------------------------------------------------------------------------------
STEP 5: RESULTS ANALYSIS
--------------------------------------------------------------------------------
Once the orchestrator iterates through all .elf files in the compiled/ directory, 
it will generate a log file in your_program/ (final_results_standard.log or 
final_results_data_only.log).

Metric Definitions:
* Masked:     The fault was injected, but the application naturally survived and 
              output the correct result.
* SDC (KO):   Silent Data Corruption. The program finished normally, but the 
              mathematical output was corrupted.
* Crashes:    The fault caused an operating system kill (Segmentation Fault, 
              Abort, or Timeout).
* ASPIS Data: Your mitigation successfully intercepted a data corruption.
* ASPIS CF:   Your mitigation successfully intercepted a control-flow error.
